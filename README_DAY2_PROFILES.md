# Advanced AI — Day 2: Profiles

## Запуск

```bash
./gradlew runDeveloperAssistant
```

Используется существующая Gradle-задача `runDeveloperAssistant`.

## Профили

### Bug Fix

```text
/bugfix При длинном ответе генерация обрывается посреди Kotlin-класса. Найди причину и дай точный фикс.
```

Профиль автоматически:
- ищет релевантный код и документацию через существующий RAG;
- читает Gradle-конфигурацию и зависимости;
- добавляет git status и последние доступные логи;
- запускает `gradlew test`;
- требует точный путь файла и готовый diff/фрагмент;
- запрещает скрывать ошибки тестов и придумывать сущности.

Ожидаемая находка для демонстрации: `OllamaOptimizationProfiles.baseline` использует
`num_predict = 700`, поэтому длинный ответ может завершиться по лимиту генерации.

### Research

```text
/research Как в проекте устроен Developer Assistant: от команды пользователя до ответа Ollama?
```

Профиль исследует код и документацию, но прямо запрещает менять код. Ответ строится
по файлам, связям и потоку данных.

Альтернативный вопрос:

```text
/research Как в проекте устроено подключение MCP и какие git-инструменты доступны ассистенту?
```

### Architecture Review — усиление

```text
/architecture Как добавить единый слой проектных правил CLAUDE.md для всех ассистентов, не меняя каждый PromptBuilder?
```

Профиль ищет существующие точки расширения и выдаёт список конкретных файлов и порядок
реализации, но не заявляет, что изменения уже внесены.

## Сценарий видео

1. Показать `AssistantProfile.kt`: три инструкции, обязательные и запрещённые действия,
   форматы ответа.
2. Показать `ProfileContextCollector.kt`: RAG по коду и документации, зависимости,
   логи, git status, запуск тестов для Bug Fix.
3. Запустить `./gradlew runDeveloperAssistant`.
4. Выполнить `/bugfix ...`, показать найденный `num_predict = 700`, точный фикс и результат тестов.
5. Выполнить `/research ...`, показать ссылки на реальные файлы и отсутствие изменений кода.
6. Выполнить `/architecture ...`, показать третий профиль.
7. В конце выполнить `/status`, чтобы подтвердить, что Research и Architecture сами код не меняли.

## Что дорабатывалось после первой попытки

Для отчёта можно честно зафиксировать:
- первоначально профиль получал только документацию и не видел реализацию;
- добавлен отдельный индекс исходного кода;
- Bug Fix сначала не проверял проект — добавлен запуск `gradlew test` и передача exit code;
- ответы могли обрываться на baseline-профиле с `num_predict = 700` — для профилей создан
  отдельный generation config с `num_predict = 2200` и `num_ctx = 16384`;
- добавлены строгие форматы ответа, чтобы модель не смешивала факты, предположения и выполненные проверки.
